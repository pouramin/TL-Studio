TL Studio application code and the public documentation site use separate build paths.

## Product development

The Go launcher and TL Studio-owned local APIs live under `cmd/launcher/`.

Browser application **source** lives in TypeScript under:

```text
cmd/launcher/ui/
```

Compiled browser JavaScript is emitted under:

```text
cmd/launcher/web/
```

Do not treat generated `web/*.js` as the primary source when changing product behavior.

Before proposing browser changes:

```bash
npm install
npm run check:web
npm run build:web
go test ./...
```

## Architecture rules

- Project filesystem/Search/process/Preview capabilities belong behind TL Studio's `/local/*` APIs.
- Agent execution concepts belong behind the TL Studio-owned `/runtime/*` contract.
- Browser feature modules must not construct implementation-specific engine routes.
- Provider/Model product definitions belong to TL Studio's registry, not to browser-local vendor config.
- New editor/runtime assets must remain bundled locally rather than loaded from a CDN.
- Preview project code must stay on a separate local origin from TL Studio's control API.

## Internal engineering docs

Engineering notes live under `docs/` in the main repository.

## Public documentation

The Fumadocs site lives under `website/`.

```bash
cd website
npm install
npm run typecheck
npm run build
```

Keep user-facing language centered on **TL Studio**. Name the bundled engine only in the maintainer compatibility reference or where legal attribution genuinely requires it.


## Current dev line

The current private development line is **v0.3.0-alpha.6**.

Two boundaries are especially important when contributing on `dev`:

- Monaco is a locally bundled, lazy-loaded editor engine. Do not move file ownership, save/conflict logic, or project-path authority into Monaco.
- Remembered permission policy belongs to TL Studio in `cmd/launcher/permission_engine.go`. Keep sensitive requests interactive and keep the browser on `/local/permissions*` rather than raw engine permission routes.

Preview builds from `dev` are GitHub Actions artifacts only. Do not add npm alpha publishing or public GitHub prereleases unless the release model is deliberately changed.
