## Project boundary

The selected Project is the working boundary for TL Studio. Files, Editor tabs, Search, Terminal commands, Preview, Sessions, Changes, Agent context, Permissions, and Questions all follow the active Project.

Switching Projects clears pending composer attachments. Unsaved Editor buffers are protected before the active Project changes.

## TL Studio semantic Sessions

Stable v0.3 no longer exposes raw engine Session envelopes as the normal Browser model.

Current Session reads use launcher-owned semantic routes under:

```text
/local/sessions*
```

TL Studio projects Session metadata, Messages, activity, status, usage, and Changes into its own product-facing shapes.

Session commands use the same product boundary for:

- create;
- rename;
- delete;
- run/prompt;
- abort.

The active execution adapter translates those commands to either the native TL Studio path or the compatibility path.

## Local Session persistence

TL Studio mirrors semantic Session state into its own local state directory.

Persisted snapshots can include:

- Session metadata;
- user/assistant transcript;
- Agent/Model selection;
- usage/activity history;
- file Changes.

This means history can remain readable even if compatibility-engine history disappears. A persisted-only Session can still be renamed or deleted locally.

TL Studio records whether a Session is owned by native execution or the compatibility path so native semantic history is not accidentally overwritten by compatibility reads.

## Live activity

Browser updates arrive through TL Studio's semantic SSE endpoint:

```text
/local/events
```

The event surface projects changes into product concepts such as Session state, Message changes, workspace changes, and attention requests for Permissions or Questions.

Native runs and compatibility runs share the same Browser event architecture.

## Legacy Sessions

A narrow read-only bridge remains for Sessions created during an older alpha protocol window. Those histories are Project-scoped and are not mutated through the legacy bridge.

## Usage

Where data is available, TL Studio shows per-turn and Project-level totals such as tokens, requests, elapsed time, Reasoning, and cache usage. These are local workspace summaries, not telemetry sent to a TL Studio cloud service.
