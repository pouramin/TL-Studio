title: File attachments

TL Studio can send local files with a prompt as structured attachment parts through its local Agent runtime contract. You can attach working material without moving the project into a hosted TL Studio service.

## Ways to attach files

Use any of these from the composer:

- click the **+** attachment button and choose one or more files;
- drag files onto the composer;
- paste files from the clipboard into the prompt field.

Selected files appear as attachment chips before you send. You can remove individual files before sending.

## Supported file types

The current UI accepts:

- images: PNG, JPEG, WebP, and GIF;
- PDF documents;
- text and common code/config formats such as Markdown, JSON, YAML, TOML, CSV, JavaScript/TypeScript, Python, Go, Rust, Java, C/C++, CSS, HTML, SQL, shell scripts, patches, `.env`, and similar text files.

SVG files are treated as text rather than image input.

## Limits

TL Studio currently enforces:

- up to **8 files** per prompt;
- up to **10 MB per file**;
- up to **20 MB total** across pending attachments.

Unsupported binary formats are rejected before the prompt is sent.

## Send behavior

The browser prepares structured attachment parts and sends them with the text Prompt through TL Studio's local Agent contract. Sent filenames remain represented in conversation history.

Pending attachments are cleared after a successful send, when you start a new Session, or when you switch Projects. If sending fails before the Prompt is accepted, the pending files remain available for retry.

## Privacy and Provider behavior

TL Studio does not upload attachments to a TL Studio-owned cloud backend. Once you send a Prompt, attachment content can still be forwarded to the Model/Provider you selected. Treat attachments with the same confidentiality rules as any other content sent to that Provider.
