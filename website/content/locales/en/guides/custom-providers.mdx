TL Studio manages compatible custom Provider definitions from **Settings → Providers** without requiring a TL Studio-hosted gateway.

## Supported provider APIs

The current form supports three protocol families:

- **OpenAI Compatible**
- **OpenAI Responses**
- **Anthropic Messages**

The form is intentionally vendor-agnostic. You provide the endpoint and Model details instead of choosing from a hard-coded vendor preset.

## Add a provider

Open **Settings → Providers → Add provider** and enter:

- Provider ID;
- display name;
- protocol;
- Base URL;
- API key;
- Model ID and optional display name;
- optional context and output limits;
- Tool Calling support;
- Reasoning support.

After saving, the Provider/Model definitions become part of TL Studio's local configuration and are translated to the active Agent engine behind the runtime adapter.

## TL Studio owns the provider registry

Custom Provider definitions are persisted by TL Studio in a versioned `providers.json` file under TL Studio's local application state.

That file contains TL Studio concepts only: Provider ID/name, protocol, Base URL, Model definitions, capability flags, and optional limits. Engine package names and implementation-specific configuration shapes are deliberately excluded.

On the first run after upgrading from older alpha builds, if no TL Studio provider registry exists yet, TL Studio can import compatible custom Provider definitions from the older runtime configuration. After that migration, the TL Studio registry becomes the source of truth for managed definitions.

## API keys are separate

API keys are **not** written into `providers.json` and are not stored in browser storage.

In v0.2, credential persistence is still delegated to the bundled engine's local credential store. Moving credentials into a TL Studio-controlled secure store is a separate future milestone.

Removing a managed Provider removes its translated engine configuration and the matching local credential entry.

## Context and output limits

If you know a custom Model's context or maximum output limit, enter it. Accurate limits help the execution layer handle longer conversations more reliably.

## Security note

A custom Base URL receives the prompts and Model requests sent through that Provider. Only add endpoints you trust, and never publish API keys in screenshots, logs, Issues, or bug reports.
