TL Studio is designed as a local application rather than a remotely exposed coding service.

## Loopback-only control surface

The browser-facing server accepts loopback addresses only. The bundled Agent engine also runs on loopback and is not exposed to the browser as a separate public endpoint.

Each launch creates a fresh random backend credential that remains server-side. TL Studio injects engine authentication through its local adapter.

## Browser origin checks

Browser requests are validated against the local control origin and the UI is served with a restrictive Content Security Policy.

## Project filesystem boundary

Browser file operations are constrained to the selected Project.

TL Studio rejects path traversal, symlink-parent escapes, project-root mutation, and protected Git metadata mutations. Direct symlinks are not treated as normal editable files.

Normal saves use a revision token so external changes cannot be silently overwritten.

## Preview isolation

Project web code does not run on TL Studio's privileged control origin. Live Preview uses a separate loopback origin and only accepts local Preview URLs.

## Local editor assets

Editor code and syntax-color assets are bundled locally. TL Studio does not load editor runtime code or workers from a CDN.

## Terminal trust

Terminal commands execute locally with your user account's permissions. Loopback isolation does not make an unsafe command safe; review destructive or credential-sensitive commands before running them.

## Provider credentials

Custom Provider definitions belong to TL Studio, but v0.2 still delegates API-key persistence to the bundled engine's local credential store. Keys are excluded from TL Studio's `providers.json` and browser storage.

## Agent permissions

An Agent can read/write project files and execute commands when the relevant Permission is granted. Review sensitive Permission requests before approving them.
