## TL Studio does not open a browser

The local server may still be running. Copy the `Local:` URL printed in the terminal and open it manually. If you used `--no-browser`, this is expected.

## Project picker does not accept a folder

Choose an existing directory. TL Studio normalizes and validates the path before switching Project context.

## A file will not save because it changed on disk

TL Studio detected that the File revision changed after you opened it. This protects newer Agent/Git/external edits from being silently overwritten.

Review the disk change first. Use force-save only when you intentionally want your editor buffer to replace the newer disk version.

## Unsaved tabs block Project switching

Save the dirty tabs or explicitly choose to discard them. TL Studio protects unsaved editor state before changing Project context.

## Project Search does not show a file

Search skips binary/non-UTF-8 files, symlinks, and common generated/heavy directories such as `.git`, `node_modules`, `dist`, `build`, `out`, `coverage`, and `.next`. Also check your include/exclude patterns and case-sensitive setting.

## A Terminal program expects an interactive TTY

The current Terminal is a project command runner, not a full PTY. Interactive TUI applications may not work correctly in v0.2.

## Preview is unavailable

Automatic Preview currently supports either:

- a root `index.html`; or
- a `package.json` project with a `dev` script.

For another stack, run its development command manually in Terminal.

## Preview starts but no URL appears

For Node projects, TL Studio detects loopback URLs reported by the development server. Make sure the dev server actually starts and reports a local URL. External/non-loopback Preview URLs are intentionally rejected.

## Bundled engine not found

Official TL Studio portable releases include the compatible Agent engine. This error is more likely when running from source or using `--runtime-bin`.

## An attachment is rejected

Current limits are **8 files**, **10 MB per file**, and **20 MB total**. Unsupported binary formats are rejected before send.

## Models or Providers are missing

For a Custom Provider, check **Settings → Providers**, Base URL, protocol, Model ID, and API-key state.

TL Studio v0.2 owns the Provider/Model definition registry. If you upgraded from an older alpha build, compatible definitions are imported on first use only when no TL Studio registry exists yet.

## A Provider request ended after retries

Retryable upstream failures can expose **Resume** after the retry cycle ends. Existing file changes remain in the workspace so the task can continue from the current state.

Authentication, quota/usage-limit, context-overflow, and similar terminal failures should be fixed at the Provider/account level first.

## Why is “Always allow these” missing?

Persistent approval is shown only when reusable matching rules are available and the Permission class can safely support persistence. Sensitive requests can require explicit approval every time.

## Agent is waiting

Check for a pending Permission request or interactive Question.

## Reporting a bug

Include your operating system, TL Studio version, reproduction steps, and non-secret error output. Include Agent-engine compatibility details only when the issue appears runtime-specific. Never publish API keys or Provider tokens.
