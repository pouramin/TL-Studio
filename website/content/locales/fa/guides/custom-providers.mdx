TL Studio تعریف Custom Providerها را از **Settings → Providers** مدیریت می‌کند و برای این کار به Gateway ابری متعلق به TL Studio نیاز ندارد.

## Provider APIهای پشتیبانی‌شده

Form فعلی از این Protocol Familyها پشتیبانی می‌کند:

- **OpenAI Compatible**
- **OpenAI Responses**
- **Anthropic Messages**

این بخش عمداً Vendor-agnostic است. Endpoint و Model را خودتان مشخص می‌کنید و Vendor Preset ثابت داخل Product وجود ندارد.

## اضافه‌کردن Provider

از **Settings → Providers → Add provider** این موارد را وارد کنید:

- Provider ID؛
- Display Name؛
- Protocol؛
- Base URL؛
- API Key؛
- Model ID و Display Name اختیاری؛
- Context و Output Limit اختیاری؛
- پشتیبانی Tool Calling؛
- پشتیبانی Reasoning.

بعد از Save، تعریف Provider و Model وارد Local Configuration خود TL Studio می‌شود و Launcher آن را پشت Runtime Adapter برای Agent Engine فعال ترجمه می‌کند.

## Provider Registry متعلق به TL Studio است

تعریف Custom Providerها توسط خود TL Studio داخل فایل Versioned به نام `providers.json` در Local App State ذخیره می‌شود.

این فایل فقط Conceptهای خود TL Studio را نگه می‌دارد: Provider ID/Name، Protocol، Base URL، Model Definition، Capability Flag و Limitهای اختیاری. Engine Package Name یا Config Shape مخصوص Implementation داخل این Registry ذخیره نمی‌شود.

در اولین اجرا بعد از Upgrade از Alphaهای قدیمی، اگر Registry خود TL Studio هنوز وجود نداشته باشد، برنامه می‌تواند Custom Providerهای سازگار را از Config قدیمی Import کند. بعد از این Migration، Registry خود TL Studio Source of Truth تعریف‌های مدیریت‌شده است.

## API Key جداست

API Key داخل `providers.json` یا Browser Storage ذخیره نمی‌شود.

در v0.2 نگه‌داری Credential هنوز به Local Credential Store مربوط به Engine همراه برنامه سپرده شده است. انتقال Credential Ownership به Secure Store خود TL Studio یک Milestone جدا برای آینده است.

با حذف Provider مدیریت‌شده، Config ترجمه‌شده در Engine و Credential محلی متناظر هم پاک می‌شوند.

## Context و Output Limit

اگر Context Limit یا Max Output مربوط به Model را می‌دانید، وارد کنید. Limit دقیق به Execution Layer کمک می‌کند Taskهای طولانی را قابل‌اعتمادتر مدیریت کند.

## نکته Security

Custom Base URL محتوای Prompt و Model Request را دریافت می‌کند. فقط Endpoint قابل‌اعتماد اضافه کنید و API Key را داخل Screenshot، Log، Issue یا Bug Report منتشر نکنید.
