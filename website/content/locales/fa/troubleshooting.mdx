## Browser خودکار باز نشد

ممکن است Local Server همچنان در حال اجرا باشد. آدرس `Local:` را از Terminal کپی و دستی باز کنید. اگر `--no-browser` داده‌اید، این رفتار طبیعی است.

## Folder Picker پوشه را قبول نمی‌کند

یک Directory موجود انتخاب کنید. TL Studio قبل از Project Switch مسیر را Normalize و Validate می‌کند.

## File به‌دلیل تغییر روی Disk Save نمی‌شود

TL Studio تشخیص داده Revision فایل بعد از بازشدن تغییر کرده است. این کار جلوی Silent Overwrite شدن تغییر جدید Agent، Git یا برنامه دیگر را می‌گیرد.

اول Disk Change را بررسی کنید. Force Save را فقط وقتی استفاده کنید که عمداً می‌خواهید Editor Buffer نسخه جدید روی Disk را جایگزین کند.

## Unsaved Tab جلوی Project Switch را می‌گیرد

Dirty Tabها را Save کنید یا آگاهانه Discard را انتخاب کنید. TL Studio قبل از عوض‌کردن Project از Unsaved Editor State محافظت می‌کند.

## Project Search یک File را نشان نمی‌دهد

Search فایل Binary/Non-UTF8، Symlink و Directoryهای Generated/سنگین مثل `.git`، `node_modules`، `dist`، `build`، `out`، `coverage` و `.next` را Skip می‌کند. Include/Exclude Pattern و Case-sensitive Setting را هم بررسی کنید.

## برنامه داخل Terminal به Interactive TTY نیاز دارد

Terminal فعلی Project Command Runner است و Full PTY نیست. بعضی Interactive TUIها در v0.2 درست کار نمی‌کنند.

## Preview در دسترس نیست

Preview خودکار فعلاً یکی از این دو حالت را لازم دارد:

- `index.html` در Root؛
- Project دارای `package.json` و Script به اسم `dev`.

برای Stackهای دیگر Development Command را دستی در Terminal اجرا کنید.

## Preview اجرا می‌شود ولی URL پیدا نمی‌شود

در Node Project، TL Studio Loopback URL اعلام‌شده توسط dev server را تشخیص می‌دهد. مطمئن شوید Server واقعاً Start شده و Local URL چاپ می‌کند. External/Non-loopback URL عمداً رد می‌شود.

## Agent Engine همراه برنامه پیدا نمی‌شود

Release رسمی Portable، Engine سازگار را همراه خودش دارد. این Error بیشتر هنگام اجرای Source یا استفاده از `--runtime-bin` دیده می‌شود.

## Attachment رد می‌شود

Limit فعلی **8 فایل**، **10 MB برای هر File** و **20 MB مجموع** است. Binary Format پشتیبانی‌نشده قبل از Send رد می‌شود.

## Model یا Provider دیده نمی‌شود

برای Custom Provider وارد **Settings → Providers** شوید و Base URL، Protocol، Model ID و وضعیت API Key را بررسی کنید.

در v0.2 تعریف Provider/Model متعلق به Registry خود TL Studio است. اگر از Alpha قدیمی Upgrade کرده‌اید، Import تعریف‌های سازگار فقط در اولین استفاده و زمانی انجام می‌شود که Registry خود TL Studio هنوز وجود نداشته باشد.

## Provider بعد از Retryها متوقف شد

Failure قابل‌Retry می‌تواند بعد از پایان Retry Cycle دکمه **Resume** نشان دهد. File Changeهای قبلی حفظ می‌شوند و Task از Workspace State فعلی ادامه پیدا می‌کند.

Authentication، Quota/Usage Limit، Context Overflow و Errorهای نهایی مشابه را باید اول در Provider/Account رفع کنید.

## چرا Always allow these نمایش داده نمی‌شود؟

Persistent Approval فقط وقتی نمایش داده می‌شود که Rule قابل‌استفاده موجود باشد و Permission Class اجازه نگه‌داری امن آن را بدهد. Request حساس ممکن است هر بار Approval صریح بخواهد.

## Agent منتظر مانده

Permission Request یا Question باز را بررسی کنید.

## گزارش Bug

OS، نسخه TL Studio، مراحل Reproduce و Error غیرحساس را بفرستید. جزئیات Agent Engine را فقط وقتی اضافه کنید که مشکل ظاهراً Runtime-specific است. API Key یا Provider Token را منتشر نکنید.
